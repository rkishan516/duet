# duet

The Duet wire protocol in **pure Dart**. No Flutter dependency, no plugin, no
platform channels — just `dart:convert` and a transport you supply.

Duet is a Rust host that owns shared application state, with guests — a Flutter
engine, a `wry` webview — reading and writing that state over a tagged-JSON
protocol. This package is the Dart half of that protocol.

## What is in the box

| Layer | Types | Rust peer |
|---|---|---|
| Values | `DuetValue`, `DuetNull` … `DuetMap` | `duet_core::Value`, `duet-codec` |
| Paths | `DuetPath`, `DuetSegment` | `duet_core::Path` |
| Envelope | `DuetRequest`, `DuetResponse`, `DuetPush` | `duet-protocol` |
| Client | `DuetClient`, `DuetTransport` | `window.__duet` in `duet-webview` |

## Using it

```dart
import 'package:duet/duet.dart';

final DuetClient duet = DuetClient(myTransport)..start();
duet.onPush = (DuetNotification note) => print('${note.path} = ${note.value}');

await duet.set('editor.zoom', const DuetFloat(1.5));
final DuetValue? zoom = await duet.get('editor.zoom');
final DuetSubscription sub = await duet.subscribe('editor');
await duet.unsubscribe(sub.id);
```

## Supplying a transport

`DuetTransport` is two members, and it is the whole seam between this package
and the outside world:

```dart
abstract interface class DuetTransport {
  Future<String?> send(String request);
  set onPush(void Function(String message)? handler);
}
```

In a Flutter app, `duet_flutter` implements it with a `BasicMessageChannel`
named `duetChannelName` (`duet/rpc`). In a browser, a websocket, or a test, it
is whatever carries text both ways.

That indirection is not architecture for its own sake. `package:flutter/services.dart`
cannot be *loaded* under `dart test` — importing it is a compile error
(`Dart library 'dart:ui' is not available on this platform`), not a lint. With
the transport abstracted, the entire wire format is exercised by the plain Dart
SDK, so conformance runs in CI in seconds instead of needing a full Flutter
install.

## Conformance

`test/wire_corpus_test.dart` runs this package against `corpus/wire-corpus.json`
at the repository root — the golden wire corpus generated by the Rust workspace
and consumed as a peer by every implementation of the format.

For each **accept** case it decodes the wire text, compares the result against a
witness written in a deliberately *different* representation (floats as IEEE-754
bits in hex, strings as UTF-8 byte arrays, maps as ordered entry arrays), and
re-encodes — byte for byte where the corpus says that is a fair demand, and
structurally where a JSON-number float makes rendering language-dependent.

For each **reject** case it asserts the message is refused, and refused for the
recorded reason: `bad_json`, `unknown_tag`, `bad_shape`, `bad_int`, `bad_float`,
`bad_base64` or `bad_path`. "It threw something" is close to asserting nothing —
a decoder broken anywhere still refuses every bad message, for a brand-new wrong
reason.

The corpus exists because four cross-language divergences have already been
found and fixed in this project, none of which a single-language round-trip test
could see: non-canonical ids causing a silent hang, `-0.0` losing its sign in
JavaScript, an id domain wider in Rust than Dart can represent, and map key
order differing between UTF-8 bytes and UTF-16 code units.

## Two things a new implementation gets wrong

Both are pinned by tests here, and both are invisible to a decode/encode
round-trip against yourself.

**Object keys must be emitted in sorted order.** The Rust host serializes
through `serde_json::Map`, a `BTreeMap`, so its output is `{"id":…,"kind":…,"path":…}`
— byte order, not declaration order. Dart's `jsonEncode` uses *insertion* order.
Every `toJson()` here goes through `sortedJsonObject` for that reason.

**Map keys sort by code point, not by `String.compareTo`.** `compareTo` compares
UTF-16 code units, so `U+1F600`'s lead surrogate `0xD83D` sorts before `U+E000`
— disagreeing with Rust, and with UTF-8 byte order. `compareDuetMapKeys` walks
`runes` instead. Any test using only ASCII keys passes under both rules and
proves nothing.
